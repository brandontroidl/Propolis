# IP Blocklist

Attacker IPs observed against a live honeypot, scored and published in ten formats.

Generated by [Propolis](https://github.com/brandontroidl/Propolis), a single-node honeypot and
threat-intelligence platform. Updated hourly.

## What makes an entry

Every IP in this list did all four of these:

1. **Connected to a honeypot service** and completed an authenticated session — not a port
   scan, not a bare TCP connect. Unauthenticated probes are recorded but never published.
2. **Did it more than once.** Single-event IPs are excluded.
3. **Scored above the publication floor** after time decay (see below).
4. **Was approved by a human.** No IP reaches this list automatically. An operator reviews the
   captured session — the commands run, the credentials tried, the files uploaded — and
   approves or rejects it individually.

That last point is the main thing separating this from an automated feed. It is also why the
list is small. It is meant to be high-confidence, not comprehensive.

## Tiers

| Tier | Raw score | Confidence | Valid for |
|---|---|---|---|
| `aggressive` | ≥ 90 | ≥ 0.95 | 24 hours |
| `standard` | ≥ 75 | ≥ 0.70 | 48 hours |

Both tiers additionally require an effective score of **≥ 50** at publication time.

Use `standard` unless you have a specific reason not to. `aggressive` is a narrower, higher-
confidence subset — appropriate for automated blocking on systems where a false positive is
cheap to recover from.

## Formats

Every tier ships in all ten formats. Substitute `standard` for `aggressive` in any path.

| File | Use with | Notes |
|---|---|---|
| `aggressive.txt` | anything | One IP per line, `#` comments |
| `aggressive.cidr` | anything | Host routes (`/32`, `/128`) |
| `aggressive.json` | APIs, tooling | Structured, includes per-entry metadata |
| `aggressive.csv` | spreadsheets | Header-less |
| `aggressive.ipset` | Linux ipset | `ipset restore < aggressive.ipset` |
| `aggressive.nft` | nftables | Defines `$propolis_aggressive` |
| `aggressive.pf` | OpenBSD/FreeBSD pf | Table file |
| `aggressive.alias` | pfSense / OPNsense | URL Table alias source |
| `aggressive.hosts` | DNS sinkhole | Reverse-DNS (`in-addr.arpa`) entries, IPv4 only |
| `aggressive.rpz` | BIND RPZ | `rpz-ip` triggers, IPv4 only |

`manifest.json` carries the build timestamp, per-tier entry counts, and validity windows.

### pfSense / OPNsense

Firewall → Aliases → URLs. Point a URL Table alias at:

```
https://raw.githubusercontent.com/brandontroidl/blocklist/main/aggressive.alias
```

Set the refresh frequency to 1 day. The alias updates itself.

### nftables

```bash
# Fetch alongside your ruleset, then include it
include "/etc/nftables.d/aggressive.nft"

# Reference the set in a rule
nft add rule inet filter input ip saddr $propolis_aggressive drop
```

### ipset + iptables

```bash
curl -sO https://raw.githubusercontent.com/brandontroidl/blocklist/main/aggressive.ipset
ipset restore < aggressive.ipset
iptables -I INPUT -m set --match-set propolis_aggressive src -j DROP
```

### pf

```
table <propolis> persist file "/etc/pf/aggressive.pf"
block in quick from <propolis>
```

## Scoring

Scores are not cumulative counters. They decay.

- **Half-life: 6 hours.** An IP that stops attacking falls out of the list on its own. A score
  of 100 decays to 50 in six hours of silence, 25 in twelve.
- **Deduplication: 60 seconds.** Repeat sightings of the same signal from the same IP inside
  one minute are recorded but add no weight, so a single burst cannot inflate a score.
- **Multi-vantage bonus.** An IP seen across multiple WAN addresses scores higher: +15% per
  additional vantage, capped at +60%. Scores are capped at 100 regardless.

The practical effect: presence in this list means *recently and repeatedly* hostile, not
"was hostile once, months ago."

## Never included

Filtered unconditionally, regardless of observed behavior:

- RFC 1918 private space (`10/8`, `172.16/12`, `192.168/16`)
- RFC 5737 documentation ranges (`192.0.2/24`, `198.51.100/24`, `203.0.113/24`)
- Loopback, link-local, multicast, limited broadcast
- IPv6 equivalents: `::1/128`, `fe80::/10`, `fc00::/7`, `ff00::/8`, `2001:db8::/32`
- Any operator-configured allowlist or explicit delist entry

The filter runs at build time and again at publish time, independently.

## Caveats

Read these before automating anything against this list.

- **One sensor.** This is a single node, not a distributed sensor network. Coverage is narrow.
  Absence from this list means nothing.
- **Shared and dynamic addressing.** An IP can be reassigned, or NAT many users. Blocking one
  may affect people unrelated to the attacker. The decay window limits but does not eliminate
  this.
- **No warranty.** Provided as-is. You are responsible for what you block. Test against your
  own traffic before enforcing anything in production.
- **Not a reputation service.** These are observations from one honeypot, not a judgment about
  any network or operator.

Found a false positive? Open an issue with the IP and I will delist it.
